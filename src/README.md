# src 目录说明

本目录存放 Minecraft Reborn 的全部源码，按客户端、服务端、公共模块三大子系统划分。

## 目录结构树

```text
src/
├── client/     # 客户端渲染、输入、UI、网络、世界状态
├── common/     # 客户端和服务端共享的类型、协议、世界与实体基础设施
└── server/     # 服务端应用层、维度、同步、命令、世界逻辑
```

## 文件介绍

- `client/`：单客户端运行时，只维护一个当前已加载维度的 `ClientWorld`。
- `common/`：跨端复用层，包含协议包、实体、方块、世界、工具库等。
- `server/`：多维度服务端实现，世界访问通过维度管理器和玩家维度路由完成。

## 内部模块关系

- `client/` 和 `server/` 都依赖 `common/`。
- `server/` 负责权威世界状态，`client/` 负责当前维度的渲染与本地表现。
- 多维度逻辑只在服务端完整持有；客户端通过维度切换重置当前 `ClientWorld`。

## 外部依赖关系

- 上层构建系统通过根目录 `CMakeLists.txt` 编译本目录全部源码。
- 测试目录 `tests/` 会分别引用 `client/`、`common/`、`server/` 中的实现。

## 容易踩的坑

- 不要绕过目录链 README 直接猜实现，进入子目录前先读对应 README。
- 服务端不允许再回到“主世界快捷访问”思路；共享存储、命令源世界、玩家世界都应走显式入口。
- 客户端虽然只有一个 `ClientWorld`，但网络层区块包已经携带维度，接入侧必须保留维度校验。
