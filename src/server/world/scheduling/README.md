# 世界任务调度

## 目录结构

```text
scheduling/
├── AreaTaskScheduler.hpp   # 每世界的区域依赖调度门面
├── AreaTaskScheduler.cpp   # 坐标队列、执行资格、取消及完成收尾
└── README.md              # 模块边界与生命周期约束
```

## 内部模块关系

每个坐标维护按优先级和提交 ID 排列的任务队列。任务在全部覆盖坐标上取得执行资格后，才提交计算池；更高优先级任务可撤回尚未执行任务的资格，旧执行凭证失效后直接返回。开始执行后保持区域占用，直到任务及回调完成，再推进受影响的后继任务。

## 上下游外部依赖关系

`ServerChunkManager` 每世界持有一个调度器。`ChunkTaskScheduler`、加载与运行时光照、区块序列化共享该实例。底层依赖 `ITask`、`UniversalWorkerPool`、`ChunkPos` 和标准库；不创建线程，不修改 IO 或客户端 mesh 池的调度策略。

## 容易踩的坑

- 不同世界必须使用不同实例，同一世界的光照与序列化必须共用实例。
- 等待区域的任务不进入计算池，计算池空闲不代表世界区域任务已全部完成。
- 关闭世界时先停止生成需求，调用区域调度器 `shutdown()`，再排空计算池，最后销毁世界数据。旧执行凭证仍可能短暂存在于计算池中。
- 取消收尾和完成回调在区域锁外执行，可以提交新任务；回调内不能等待自身调度器完成。
- 执行器只能在区域调度器空闲时替换；执行器必须存活至世界任务及旧执行凭证全部排空。
- 区域执行依赖与生成依赖图的 `ReentrantAreaLock` 职责不同，不能用方块写半径替代依赖图的访问范围。
