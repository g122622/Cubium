# 实体生成与消失

## 目录结构

```
spawn/
├── NaturalSpawner.hpp/cpp # 自然生成循环、生成条目选择与数量上限协调
├── DespawnManager.hpp/cpp # 生物消失距离、持久化与和平难度处理
├── VillageSiege.hpp/cpp # 村庄围攻调度及僵尸生成
├── WanderingTraderSpawner.hpp/cpp # 流浪商人调度与候选位置检查
└── README.md
```

## 内部模块关系

`NaturalSpawner` 先筛选分类与可生成区块，再执行成组生成尝试。全局数量上限由
`EntityDensityManager` 管理，每玩家每分类的局部上限由 `LocalMobCapCalculator` 管理。
放置类型和实体自身谓词统一交给 `EntitySpawnPlacementRegistry`，不再按分类追加光照条件。
`DespawnManager` 负责存量实体，两个事件生成器独立调度并复用公共生成检查。

## 上下游外部依赖关系

上游：`ServerWorld`、世界区块与玩家查询、`MobSpawnInfo`、实体注册表、难度和游戏规则；
`IWorldSpawnAdapter` 提供方块、流体、光照、环境属性、维度门槛与附近玩家。

下游：服务端世界 tick、维度实体管理器与实体生成入口。实体加入世界前调用
`MobEntity::finalizeSpawn`，传入真实难度和生成原因；区块首次动物生成由
`server/world/gen/spawn` 单独驱动。

## 容易踩的坑

1. **分类与谓词各有职责**：分类决定生成条目、全局/局部上限和调度频率，实体谓词决定
   光照及环境。未注册谓词的类型直接通过谓词层，不能增加分类光照兜底。
2. **位置与谓词分开**：自然生成先检查放置类型，再运行谓词；村庄围攻只运行僵尸的事件
   生成谓词。位置提前失败时，不应继续消耗谓词随机数。
3. **光照存在两层数值**：原始天空光/方块光与衰减后的综合亮度不同；雷雨使用天空衰减 10。
   主世界的亮度门槛还会随机采样，下界和末地使用各自的常量门槛。
4. **两种刷怪笼原因不同**：普通刷怪笼保留光照要求；试炼刷怪笼忽略光照。两者都可跳过
   通用的脚下生成支撑检查，不能把普通刷怪笼统一当作任意光照生成。
5. **高度图返回空气位置**：`getTopBlockY` 返回方块 Y，世界读取适配器需要加 1；生成期间
   同样如此，蝙蝠地表检查尤其依赖这个语义。
6. **数量上限按分类统计**：全局上限为 `maxInstancesPerChunk × spawnableChunkCount / 289`；
   生物加入后需同时占用全局和局部配额。群系条目分类和实体分类错配会使统计失效。
7. **地表史莱姆使用位置环境属性**，地下史莱姆另取世界种子和区块坐标；它们不共用随机源。
8. **生成原因必须贯穿初始化**：自然生成为 `Natural`，村庄围攻为 `Event`，首次区块生成为
   `ChunkGeneration`，僵尸增援为 `Reinforcement`。
