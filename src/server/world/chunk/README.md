# 服务端区块运行时与唯一门面

## 目录结构树

```text
chunk/
├── base/  # 跨能力共享的值类型与交接协议
├── diagnostics/  # 状态和内存诊断快照
├── integration/  # 区块接入世界的激活、光照与退场
├── lifecycle/  # 生命周期用例编排与内部能力
├── ServerChunkManager.cpp  # 服务端区块子系统唯一生产门面
└── ServerChunkManager.hpp  # 服务端区块子系统唯一生产门面
```

## 内部模块关系

门面委托生命周期控制器；控制器连接需求、来源、生成、卸载和世界接入。注册表统一持有实例与 FULL 索引。

## 上下游外部依赖关系

公共游戏逻辑通过 IChunkManager 使用门面；世界、维度、网络和命令使用服务端门面。内部依赖公共数据、生成算法、存储和世界区域执行器。

## 容易踩的坑

- 数据达到阶段、FULL 发布、世界激活、光照可发送和模拟资格分别表达。内部调度器和需求容器不暴露给生产调用方。
- 迁移源文件时同步更新全部消费目标的包含路径与唯一 CMake 编译归属。
