# 区块光照数据

## 目录结构树

```text
light/
├── SWMRNibbleArray.hpp/cpp  # 区块持有的 4 bit 光照数组、发布与缓冲所有权
└── EmptinessMap.hpp/cpp     # 按段记录空气状态的辅助容器
```

## 内部模块关系

`ChunkData` 内嵌天空光与方块光两组 `SWMRNibbleArray`。更新侧由光照写任务操作，
可见侧经 `updateVisible()` 发布。数组所有权与观察指针分离；未发布写缓冲、可见缓冲、
退役缓冲分别由对应所有者管理。

`EmptinessMap` 提供独立的段空气状态容器；当前服务端引擎经 `IChunk` 访问的空映射，
由 `ChunkData` 内嵌的布尔数组承接。

## 上下游外部依赖关系

- 依赖公共类型、世界尺寸及区块接口，不依赖服务端。
- 服务端光照引擎修改更新侧，世界光照查询和网络导出读取可见侧。
- `ChunkData` 生命周期决定数组生命周期；临时缓冲可进入调用线程的有界对象池。

## 容易踩的坑

- 主世界每层有 26 个光照段，两层合计 52 个槽位；包括上下各一段缓冲。
- Null、Uninit、Hidden 的逻辑语义不同；天空光 Null 的回溯由世界光照管理器解释。
- Hidden 保留方块光数据以支持减亮计算，不能当作整个区块卸载或直接清空。
- `toByteArray()` 只导出部分可见数据，不能用于统计全部缓冲所有权。
- 退役数组保留到析构或再次发布时复用；每线程对象池最多保留 64 块 2048 B 数组。
- 原子指针不保证数组字节并发读写安全；原地发布和退役复用存在代码中标注的并发限制。
