# 区块加载与追踪

## 目录结构

```text
load/
├── ChunkDistanceGraph.hpp/cpp      # 区块加载级别传播
├── ChunkLoadLevel.hpp              # 加载级别常量与换算
├── ChunkLoadTicket.hpp             # 票据类型及集合
└── ChunkLoadTicketManager.hpp/cpp  # 显式票据、玩家来源与追踪范围
```

## 内部模块关系

票据管理器汇总加载来源并更新距离图；玩家追踪集合独立驱动区块发送与卸载回调。

## 上下游外部依赖关系

依赖公共坐标、距离图和票据值类型；ServerChunkManager 消费加载变化，ChunkSendManager 消费追踪变化。

## 容易踩的坑

- 玩家请求视距与服务器上限分别保存，追踪范围取二者较小值；改变上限必须保留原请求。
- 同一坐标上的多名玩家可有不同追踪范围；不要把请求视距写成全局视距。
- 追踪中心更新先于区块发送；缩小视距通过 leave 回调卸载旧区块。
- 玩家离开时清除其视距偏好，跨维度加入时从连接状态重新应用。
- `hasTicket` 查询原始显式票据；距离图级别还包含邻居传播，不能用它判断某种票据是否仍存在。
- 卸载冷却使用 `ChunkPyramid::maxLevel()`，仅保留现有持有者；使用 Border 级会重新触发生成。
- 距离图每次推进同时受节点数与墙钟预算约束；一次调用不保证所有级别收敛，必须继续逐 tick 推进。
- 玩家加载距离不能充当模拟距离；方块 tick 使用调用方传入的实体模拟距离再加一圈，显式强票据通过独立来源索引保留原有传播半径。
