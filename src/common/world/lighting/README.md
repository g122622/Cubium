# 公共光照基础设施

## 目录结构树

```text
lighting/
├── LightType.hpp               # 天空光与方块光类型
├── IChunkLightProvider.hpp     # 光照计算所需的区块、维度与更新通知接口
├── LightEngineUtils.hpp/cpp    # 光照坐标、方向和方块面遮挡工具
└── InternalLightUtils.hpp/cpp  # 天体角度、天空减暗与月相计算
```

## 内部模块关系

`LightType` 和 `StarLightLightingProvider` 定义跨模块协作基础。`LightEngineUtils`
封装公共的方向和遮挡计算，`InternalLightUtils` 提供时间与天空环境计算。

传播引擎与世界读取门面位于 `server/world/lighting/`；光照数组及空气段辅助容器位于
`common/world/chunk/data/light/`。本目录不持有光照缓冲或区块生命周期状态。

## 上下游外部依赖关系

- 依赖公共世界坐标、方块状态与形状，以及时间计算基础设施。
- 服务端世界实现光照提供者，生成/加载/运行时光照任务经该接口驱动传播。
- 公共方块行为需要面遮挡和天体计算，因此这些工具留在 common，不能依赖 server。
- 光照计算结果由区块持有，游戏规则和网络通过世界光照读取入口使用已发布数据。

## 容易踩的坑

- 目标行为参照原版 1.21.11；不要将旧版本描述或旧实现注释当作当前协议、算法的证据。
- 主世界有 24 个方块段，每类光照额外包含上下各一段，两层合计 52 个槽位。
- 空段、Null、Uninit、Hidden 和有效全零光照不是同一语义。天空光 Null 要经空映射和
  向上回溯解释，方块光 Hidden 则保留减亮计算所需的数据。
- 区块卸载由区块/任务所有权协调；光照引擎只清理本次操作缓存，不维护长期区块列集合。
- 传播写任务由世界区域调度串行；当前可见侧的原子指针不能保证数组字节没有数据竞争，
  必须同时检查 `SWMRNibbleArray` 的发布、退役与回收约束。
- 内存统计应计算唯一缓冲所有者、退役数组、线程池及 TLS 队列容量；导出 vector 的长度
  只代表部分可见数据。静态估算与历史基准复核见光照内存交接文档。
- 从临时 nibble 移入区块后，必须重新绑定引擎缓存再发布，避免发布已经被移空的对象。
- 源面遮挡要保留发光方块的传播规则；增加与减少路径也不能机械共用所有门控条件。
- 天体角度辅助函数有不同计算用途，调用时应核对具体函数；不要仅凭名称互换。
- 测试中的世界须完成初始化后才能通过 `ServerWorld::setBlockState()` 触发光照任务。
