# 实体状态查询

## 目录结构树

```text
query/
└── EntityStateQuery.hpp/cpp # 活动组件、原生装备、归属、变种与 Molang 具名查询的统一只读入口
```

## 内部模块关系

门面优先读取 addon 活动组件；原生实体状态由对应实体公开接口提供。装备查询将过滤域映射为实际装备槽位，背包域独立访问储物槽位。`molangQuery` 把 `query.*` 具名查询翻译为实体当前状态，供 Molang 求值上下文注入。

## 上下游外部依赖关系

实体过滤器、脚本组件和 Molang 求值上下文共同调用本目录；依赖公共实体、物品、背包以及 addon 实例组件，不依赖脚本引擎或服务端实现。

## 容易踩的坑

- is_owner 比较调用者记录的主人 UUID 与所选主体，不能颠倒主从关系。
- 玩家背包域不包含护甲和副手；马类储物域跳过鞍和马铠槽。
- 基岩变种编号不等于 Java 变种枚举编号，缺少映射时必须明确报错。
- `molangQuery` 里"已实现但该实体不适用"必须返回 0，只有真正未实现的查询才返回 nullopt（上层会按未实现记 warn），两者混用会产生误导性日志。
- 查询名一律小写并带 `query.` 前缀，解析器已把 `q.` 别名与大小写归一，这里不要重复处理。
