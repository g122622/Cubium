# 实体事件程序

## 目录结构树

```text
events/
├── EntityEventProgram.hpp/cpp # 事件动作校验、属性与组件组计算、顺序和加权随机执行
└── AddonEntityEvents.hpp/cpp # 实例事件入口、首次生成状态和通知出口弱引用
```

## 内部模块关系

定义加载时编译事件程序及其 Molang 表达式。实体事件组件持有不可变程序，先按完整主体上下文求值动作过滤器，执行完成后暂存声明属性和组件组操作，并发送实际触发的事件 ID 与组件组修改快照。首次生成事件由实体 tick 驱动。

## 上下游外部依赖关系

实体定义工厂和 Entity.triggerEvent 使用事件组件；脚本门面通过弱引用出口将触发通知放入后置事件总线。依赖公共实体、随机数、属性状态和 Result。

## 容易踩的坑

- 属性先计算、后提交，递归或步骤预算失败不得留下部分写入。
- 事件数值赋值限制在声明范围，脚本 setProperty 对越界值报错，两种入口不能混用校验行为。
- 生成事件仅执行一次，反序列化工厂不能重放生成逻辑。
- 事件出口由脚本门面拥有，实体只持弱引用；门面关闭后实体仍可安全执行自身程序。
- 随机动作使用实体已有随机源，零权重不参与选择。

- 事件表达式读取本 tick 已生效属性，不能看见之前排队但尚未生效的写入；求值失败不提交整次事件的属性或组件组操作。

- 过滤器返回不匹配时仅跳过该动作；返回错误时整次事件不提交属性和组件组操作。
