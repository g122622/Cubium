# 实体过滤条件

## 目录结构树

```text
filters/
├── base/ # 官方基础家族的不可变元数据
└── EntityFilter.hpp/cpp # 条件校验、逻辑组合、主体选择和当前实体状态比较
```

## 内部模块关系

编译入口验证并规范化比较操作符、主体和参数，求值入口读取宿主提供的当前实体上下文。属性比较使用声明类型和枚举顺序，家族读取当前活动组件。装备、归属和变种通过 query 门面读取当前实体状态。

## 上下游外部依赖关系

由实体事件程序使用，可复用于行为与实体查询；依赖公共实体、世界状态、声明属性及活动组件，不依赖服务端或脚本引擎。

## 容易踩的坑

- other、player、parent、damager 和 target 必须由真实交互上下文提供，缺失主体不匹配条件。
- 属性类型必须匹配指定测试，缺失属性不能因为不等比较而意外通过。
- 枚举有序比较使用声明中的顺序，不能使用字符串字母顺序。
- 逻辑组合必须短路；未执行分支不能产生原版家族或组件映射错误。
- 家族来源需要权威定义，不能把 Java 实体类名直接当作基岩家族。

- 装备物品名称补齐 minecraft 命名空间；inventory 域不混入护甲和副手，any 域可以匹配背包。
- has_container_open 只读取玩家当前菜单；缺失主体不能因 value=false 变成匹配。

- has_damage 只作用于本次伤害的受害者，fatal 来自已确认的死亡结果；没有伤害上下文时不匹配，包括不等比较。

- 单条件数组包装会透传到其唯一条件，并计入深度预算；隐式多条件数组尚无可靠组合语义时明确拒绝。
