# 实体定义

## 目录结构树

```text
definition/
└── AddonEntityDefinition.hpp/cpp # 实体 JSON 校验、基础组件安装与实例工厂
```

## 内部模块关系

定义解析先校验声明属性、事件程序、基础组件和组件组，再由工厂创建普通实体或有生命实体。实例共享不可变定义，工厂先计算默认表达式并安装属性，再允许保存数据恢复。

## 上下游外部依赖关系

AddonContentManager 解析并注册定义；实体注册表调用工厂，统一实体反序列化链路复用同一工厂。依赖公共实体、属性、资源标识和属性状态组件。

## 容易踩的坑

- 属性默认值必须在 NBT 恢复之前安装，不能在恢复之后覆盖保存值。
- 基类构造时虚调用看不到定义尺寸，安装定义后重新计算碰撞箱。
- 健康组件决定实例是否走有生命实体继承链，无健康组件的对象不能伪造健康状态。
- 未识别的组件、字段或行为语义应明确失败，避免静默丢弃定义内容。
- 存活实例共享原定义，脚本重载不会令其定义指针悬垂。

- 任一组件组含健康组件时，工厂使用生物继承链；组件尚未活动时不暴露脚本健康组件，也不接受生命伤害。
