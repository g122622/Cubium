# 差分能力：`region_sector`

> 由 `tests/diff/README.md` 拆分而来，记录该能力的实现要点、踩坑与验证结论。
> 跨能力共性规律见 [`_patterns.md`](./_patterns.md)。

第 103 个能力，27 个索引/寻址用例全部一致。区域文件的区块索引与扇区寻址此前没有被比对过。

## 四个关键点

**1. 区块 → 区域用 `>> 5` / `& 31`，不是除法取模。**

```java
public int getRegionX()      { return this.x >> 5; }
public int getRegionZ()      { return this.z >> 5; }
public int getRegionLocalX() { return this.x & 31; }
public int getRegionLocalZ() { return this.z & 31; }
```

对**负坐标**，位移与除法/取模的结果完全不同：

| 区块坐标 | `>> 5` / `& 31` | 若用 `/ 32` 与 `% 32` |
|---|---|---|
| `-1` | 区域 **-1**、局部 **31** | 区域 0、局部 **-1** |
| `-32` | 区域 **-1**、局部 **0** | 区域 -1、局部 0 |
| `-33` | 区域 **-2**、局部 **31** | 区域 -1、局部 **-1** |

实测 `region|-1|-1` 得到 `region=(-1,-1) local=(31,31) idx=1023`。用除法的话 `-1` 会落到
区域 0、槽位 -1（越界或错误覆盖）。

**2. 槽位索引是列优先 `localX + localZ * 32`。**

| 单元 | `offsetIndex` |
|---|---|
| `(0, 0)` | 0 |
| `(31, 0)` | 31 |
| `(0, 31)` | 992 |
| `(31, 31)` | 1023 |

写成 `localX * 32 + localZ` 会得到 992 与 31 互换的结果。头表 1024 项 × 4 字节 = 4096 字节
= 恰好 1 个扇区。

**3. 偏移值是 24 位扇区号 + 8 位扇区数。**

```java
private static int getNumSectors(int offset)   { return offset & 0xFF; }
private static int getSectorNumber(int offset) { return offset >> 8 & 16777215; }
```

| 输入 | 扇区号 | 扇区数 |
|---|---|---|
| `0` | 0 | 0（空槽） |
| `514`（`0x202`） | 2 | 2 |
| `51400` | 200 | 200 |
| `131072` | 512 | 0 |
| `-1` | **16777215** | **255** |

所以单个区块最多占 **255 个扇区**（约 1 MB），最大扇区号是 **16777215**（约 64 GB 区域文件）。

**4. 扇区数溢出会被静默丢弃。**

| 单元 | `offset` |
|---|---|
| `pack(1, 255)` | 511 |
| `pack(1, 256)` | **256** |

`256 & 0xFF = 0`，所以扇区数 256 被打包成 0——**一个占整个扇区的区块会变成「0 扇区」，即
会被当作空槽**。原版写入路径会先把区块内容压缩后按扇区数分配，正常情况下不会超过 255，
但这个静默截断值得记录。

## 头部布局

区域文件的前 2 个扇区是头部：

| 偏移 | 内容 |
|---|---|
| 0 – 4095 | 偏移表（1024 × 4 字节） |
| 4096 – 8191 | 时间戳表（1024 × 4 字节） |
| 8192+ | 区块数据扇区 |

因此合法的数据扇区号 `>= 2`。读取时若见到 `sectorNumber < 2`，原版会告警并视为损坏。
