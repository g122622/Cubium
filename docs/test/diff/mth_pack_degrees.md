# 差分能力：`mth_pack_degrees`

> 由 `tests/diff/README.md` 拆分而来，记录该能力的实现要点、踩坑与验证结论。
> 跨能力共性规律见 [`_patterns.md`](./_patterns.md)。

第 139 个能力，29 个用例全部一致。`Mth.packDegrees` / `Mth.unpackDegrees` 此前未被覆盖——这对
函数是**实体旋转角的网络同步格式**。

## 核心发现一：`packDegrees` 不做 clamp，`180` 回绕成 `-128`

```java
public static byte packDegrees(float degrees) {
    return (byte) floor(degrees * 256.0F / 360.0F);
}
```

`floor(x * 256 / 360)` 的结果强转 `(byte)`——Java 的 `(byte)` **保留低 8 位**，不做饱和。

| 单元 | `x*256/360` | `floor` | `(byte)` |
|---|---|---|---|
| `pack\|0` | `0` | 0 | **0** |
| `pack\|90` | `64` | 64 | **64** |
| `pack\|179` | `127.29` | 127 | **127** |
| **`pack\|180`** | **`128`** | **128** | **`-128`** |
| **`pack\|-179`** | **`-127.29`** | **-128** | **`-128`** |
| `pack\|-180` | `-128` | -128 | **`-128`** |
| **`pack\|181`** | **`128.71`** | **128** | **`-128`** |
| **`pack\|360`** | **`256`** | **256** | **`0`** |
| **`pack\|270`** | **`192`** | **192** | **`-64`** |

**`+180` 打包成 `-128`**（而不是 `127` 或 `-127`）——这是 8 位回绕的直接后果。

### 一个隐蔽的边界塌缩

| 单元 | 结果 |
|---|---|
| `pack\|179` | **`127`** |
| **`pack\|-179`** | **`-128`** |
| **`pack\|-180`** | **`-128`** |

`-179` 的 `floor(-127.29) = -128`，与 `-180` **撞在同一字节**。而上界 `+179 → 127` 是唯一的。

**`packDegrees` 在负侧的可用分辨率比正侧少一格**——`[-180, -179)` 与 `[-179, -178)` 区间都映射到
`-128`。

### 超出值域继续回绕

`360 → 256 → 0`，`270 → 192 → -64`。**没有任何饱和保护**。

## 核心发现二：`floor` 是 `Mth.floor`（向负无穷），不是 `(int)` 截断

```java
return (byte) floor(degrees * 256.0F / 360.0F);   // 不是 (byte)(degrees * 256 / 360)
```

| 单元 | `x*256/360` | `Mth.floor` | `(int)` 截断 |
|---|---|---|---|
| **`pack\|-0.5`** | **`-0.3556`** | **`-1`** | `0` |
| **`pack\|-1.40625`** | **`-1.0`** | **`-1`** | `-1` |
| **`pack\|-2.8125`** | **`-2.0`** | **`-2`** | `-2` |
| `pack\|0.5` | `0.3556` | `0` | `0` |

**`pack\|-0.5` 的结果是 `-1`**，若用 `(int)` 截断会得 `0`。

负角度在 `x * 256 / 360` 后几乎总是负小数，因此 **`floor` 与 `(int)` 的差异在负半轴到处生效**。

## 核心发现三：`unpackDegrees` 的 `packed * 360` 是 `int` 乘法

```java
public static float unpackDegrees(byte packed) {
    return packed * 360 / 256.0F;
}
```

`packed`（`byte`）先提升为 `int`，乘 `360` 得 **`int`**，再除 `256.0F` 得 `float`。

| 单元 | 结果 |
|---|---|
| `unpack\|0` | `0` |
| **`unpack\|1`** | **`1.40625`** |
| **`unpack\|64`** | **`90`** |
| `unpack\|127` | `178.59375` |
| **`unpack\|-128`** | **`-180`** |
| **`unpack\|-1`** | **`-1.40625`** |

**分辨率是 `360/256 = 1.40625` 度**——精确的二进制小数（`1.40625 = 45/32`），因此这些值都是精确的。

若 C++ 写成 `packed * 360.0F / 256.0F`，中间结果是 `float` 而非 `int`，虽然本例数值相同，但对
非精确值可能差 1 ULP。

## 核心发现四：往返不是恒等，`+180` 变成 `-180`

```java
unpackDegrees(packDegrees(x))
```

| 单元 | 原值 | 往返结果 | 误差 |
|---|---|---|---|
| `round\|0` | `0` | `0` | `0` |
| `round\|90` | `90` | `90` | `0` |
| **`round\|100`** | **`100`** | **`99.84375`** | `-0.15625` |
| **`round\|179`** | **`179`** | **`178.59375`** | `-0.40625` |
| **`round\|-100`** | **`-100`** | **`-101.25`** | `-1.25` |
| **`round\|180`** | **`180`** | **`-180`** | **符号翻转！** |
| `round\|-180` | `-180` | `-180` | `0` |

**量化误差最大 `1.40625` 度**（半格是 `0.703125`，但 `-100` 的例子错了 `1.25`——因为 `floor` 在负侧
向下取整，误差不对称）。

**`round|180` 得 `-180`**：`+180` 打包成 `-128`，解包成 `-180`。**这是唯一会翻转符号的输入**。

### 对合法 `byte` 的往返是恒等的

`unpack(pack(unpack(b)))` 对 `b ∈ [-128, 127]` 恒等，因为 `unpack` 的输出恰好落在量化网格点上。
本能力的 `unpack` 用例直接验证了网格点值的精确性。

## 本轮情况：一次通过

写代码前完整读取了 `packDegrees` / `unpackDegrees` 的实现，**特别注意了 `floor` 不是 `(int)`**，
以及 `(byte)` 的回绕语义（用 `& 0xFF` 再转有符号实现）。
