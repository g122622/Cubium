# 差分能力：`mth_sqrt`

> 由 `tests/diff/README.md` 拆分而来，记录该能力的实现要点、踩坑与验证结论。
> 跨能力共性规律见 [`_patterns.md`](./_patterns.md)。

第 142 个能力，24 个用例全部一致。补全了 [`mth_frac`](./mth_frac.md) 文档中列出的 `Mth.sqrt`
缺口，并首次覆盖 **`Mth.fastInvSqrt`**——`Mth.atan2` 内部依赖的快速平方根倒数。

## 核心发现一：`fastInvSqrt` 的相对误差约 `1e-3`，比预期大一个量级

```java
@Deprecated
public static double fastInvSqrt(double x) {
    double half = 0.5 * x;
    long bits = Double.doubleToRawLongBits(x);
    bits = 6910469410427058090L - (bits >> 1);     // 魔数近似
    x = Double.longBitsToDouble(bits);
    return x * (1.5 - half * x * x);                // 一次牛顿迭代
}
```

魔数 `6910469410427058090L` = `0x5FE6EB50C7B537A9`，是 Quake 快速平方根倒数的双精度版本。

| 单元 | 结果 | 精确值 | 相对误差 |
|---|---|---|---|
| **`fast\|1`** | **`0.998308143`** | `1.0` | `1.7e-3` |
| **`fast\|4`** | **`0.499154071`** | `0.5` | `1.7e-3` |
| **`fast\|9`** | **`0.332952785`** | `0.3333…` | `1.1e-3` |
| **`fast\|16`** | **`0.249577036`** | `0.25` | `1.7e-3` |
| **`fast\|100`** | **`0.0998447611`** | `0.1` | `1.55e-3` |

**即使输入是完全平方数，结果也不精确。**

我最初在代码注释里估计「相对误差约 `1e-4`」，**实测是 `1e-3` 量级，大了十倍**。
原因是只做了一次牛顿迭代——理论上单次迭代可把误差平方（`1e-1 → 1e-2`），但魔数初值本身只能保证
约 `3-4` 位有效数字。

| 单元 | 结果 | 精确值 |
|---|---|---|
| `fast\|2` | `0.706929651` | `0.707106781` |
| `fast\|3` | `0.576846109` | `0.577350269` |
| `fast\|0.5` | `1.4138593` | `1.41421356` |
| `fast\|0.25` | `1.99661629` | `2.0` |
| `fast\|10` | `0.315685281` | `0.316227766` |

**`fast|0.25` 得 `1.99661629`**——相对误差 `1.7e-3`，与平方数的情况一致。

## 核心发现二：`fastInvSqrt(0)` 返回 `1.44e154`，不是 `Infinity`

**没有任何特殊值保护**——`x = 0` 时直接走位运算路径。

| 单元 | 结果 |
|---|---|
| **`fast\|0`** | **`1.44045117e+154`** |

推导：`bits(0.0) = 0`，`0x5FE6EB50C7B537A9 - 0` = 魔数本身，其作为 `double` 解释约为
`9.6e153`；再乘 `(1.5 - 0) = 1.5` → 约 `1.44e154`，与实测吻合。

**位模式到 `double` 的映射不能靠心算**——我最初估计魔数约 `1.4e153` 得 `2.1e153`，与实际相差
一个量级。这类数值必须实测。

**对比**：`1 / Math.sqrt(0.0)` = `Infinity`。两者完全不同。

## 核心发现三：负数输入返回 `Infinity`（因为 `>>` 保留符号位）

```java
bits = 6910469410427058090L - (bits >> 1);
```

**这里是有符号右移 `>>`，不是 `>>>`。**

| 单元 | 结果 |
|---|---|
| **`fast\|-1`** | **`Infinity`** |
| **`fast\|-4`** | **`Infinity`** |

负数 `x` 的 `bits` 最高位是 `1`，`>>` 会把符号位向右填充，导致减法的结果也是一个"负数位模式"，
经 `longBitsToDouble` 解释后可能是 `NaN` 或极大值，最终乘法溢出成 `Infinity`。

**若 Cubium 用 `>>>` 实现，负数输入会得到完全不同的结果**（虽然两者都没有语义意义）。

## 核心发现四：`fastInvSqrt` 在极大极小值上仍然可用

| 单元 | 结果 | 精确值 | 相对误差 |
|---|---|---|---|
| `fast\|1e100` | `9.99959194e-51` | `1e-50` | `4.1e-5` |
| `fast\|1e-100` | `9.99825376e+49` | `1e50` | `1.7e-4` |

**在指数两端误差反而更小**（`1e-5` 量级），因为魔数近似在归一化区间内效果更好。

## 核心发现五：`Mth.sqrt(float)` 走 `double` 再降回 `float`

```java
public static float sqrt(float x) {
    return (float) Math.sqrt(x);
}
```

**输入先提升为 `double`，求根后再一次舍入回 `float`。**

| 单元 | 结果 |
|---|---|
| `sqrtF\|0` | `0` |
| `sqrtF\|1` | `1` |
| `sqrtF\|2` | `1.41421354` |
| `sqrtF\|4` | `2` |
| `sqrtF\|9` | `3` |
| `sqrtF\|0.25` | `0.5` |
| **`sqrtF\|-1`** | **`NaN`** |
| **`sqrtF\|1e-40`** | **`9.99997303e-21`** |
| **`sqrtF\|3.4028235e38`** | **`1.8446743e+19`** |

**`sqrtF|1e-40` 得 `9.99997303e-21` 而不是 `1e-20`**：`1e-40` 先降为 `float`（有舍入误差），
再提升为 `double` 求根，所以偏差来自输入而非算法。

**`sqrtF|3.4028235e38`** 是 `float` 最大值的开方，得 `1.8446743e+19`——`float` 的最大值的平方根
恰好接近 `2^64`。

## 本轮踩坑：`sqrtF` 的输入必须先降为 `float`

首次运行报出 1 处差异：

```
oracle: {"value":"9.99997303e-21"}
probe : {"value":"9.99999968e-21"}
```

**我的探针写成 `std::sqrt(std::stod(parts[1]))`**——`stod` 返回 `double` 精度的 `1e-40`，
求根得 `1e-20`，再降 `float` 得 `9.99999968e-21`。

而原版的 `Math.sqrt((double) x)` 中，`x` 已经是**降过精度的 `float`**，所以 `1e-40` 的 `float`
表示（略偏离 `1e-40`）才是真正的输入。

**修正**：

```cpp
const f32 input = std::stof(parts[1]);          // 先降 float
const f64 root = std::sqrt(static_cast<f64>(input));
const f32 result = static_cast<f32>(root);
```

**教训**：当原版函数的参数是 `float` 时，探针**必须先把字符串解析成 `float`**，再按原版的方式
提升。直接用 `double` 解析会跳过中间那次舍入，导致末位差异。

这与 `_patterns.md` 里「浮点契约」一条直接相关。

## 未覆盖范围

- `Mth.invSqrt(float)` / `invSqrt(double)`（委托给 `org.joml.Math.invsqrt`，该库方法在 oracle 侧
  无法单独验证其实现，且 jar 不在本地缓存）
- `Mth.atan2`（依赖 257 项 `ASIN_TAB` / `COS_TAB`，这些表由 `Math.sin` 填充，存在 JDK 与 MSVC
  的 `sin` 差异风险）
- `Mth.SQRT_OF_TWO` 常量（静态初始化时调用 `sqrt(2.0F)`，值应与 `sqrtF|2` 一致）
- `fastInvSqrt` 在 `Mth.atan2` 实际调用链中的传播误差
