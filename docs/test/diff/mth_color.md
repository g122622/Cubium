# 差分能力：`mth_color`

> 由 `tests/diff/README.md` 拆分而来，记录该能力的实现要点、踩坑与验证结论。
> 跨能力共性规律见 [`_patterns.md`](./_patterns.md)。

第 113 个能力，27 个用例全部一致。HSV 转 RGB 与 murmur3 混合此前未被覆盖。

## 核心发现：`h = 1.0` 不是纯红，而是黄色

```java
int i = (int)(h * 6.0F) % 6;
float f = h * 6.0F - i;
float f3 = v * (1.0F - (1.0F - f) * s);
```

对 `h = 1.0, s = 1, v = 1`：

| 步骤 | 值 |
|---|---|
| `h * 6.0F` | 6.0 |
| `i = (int)6 % 6` | **0**（折回区间 0） |
| `f = 6.0 - 0` | **6.0**（不是 0！） |
| `f3 = 1 * (1 - (1 - 6) * 1)` | **6.0** |
| `g = 6.0 * 255` | 1530 → `clamp` 到 **255** |

**`hsvToArgb(1, 1, 1)` 得 `r=255, g=255, b=0`（黄色），不是纯红。**

`i` 被 `% 6` 折回 0，但 `f` 用的是**未取模的** `h * 6.0F`。两者不同步，所以 `h = 1.0` 与
`h = 0.0` **不等价**。

我在写探针注释时先按「`f` 是小数部分」的直觉断言结果应是纯红，**实测证明错了**——这是
`_patterns.md` 第五条「读源码片段下结论」的又一次实例：我读了完整方法体，却用直觉代替了
逐行代入。

### 实测对照

| 单元 | 结果 |
|---|---|
| `hsv\|0\|1\|1` | `r=255, g=0, b=0`（纯红） |
| `hsv\|1\|1\|1` | **`r=255, g=255, b=0`（黄）** |
| `hsv\|0.333333\|1\|1` | `r=0, g=255, b=0`（纯绿） |
| `hsv\|0.666667\|1\|1` | `r=0, g=0, b=255`（纯蓝） |
| `hsv\|0.833333\|1\|1` | `r=254, g=0, b=255`（品红偏蓝） |

`0.833333` 距 `5/6 = 0.8333333...` 略有偏差，`f` 的小数部分被 `×255` 放大成 254 而非 255。

## 其余三个关键点

**1. 色相区间用 `(int)` 截断 + `%`，不是 `floor`。**

对正数 `h` 两者一致。但对**负数** `h`：`(int)` 向零截断，Java 的 `%` 也返回负数，结果是
**负区间**，会落到 `default` 分支**抛 `RuntimeException`**。

`hsvToArgb(-0.1f, 1, 1)` 不是把色相环绕，而是直接抛异常。本能力没有覆盖负数色相——它属于
「错误路径」，见 `_patterns.md` 第九条。

**2. 每个通道先截断再 clamp，不是四舍五入。**

```java
clamp((int)(f4 * 255.0F), 0, 255)
```

`(int)` 截断在前：

| 单元 | R 通道 |
|---|---|
| `hsv\|0\|1\|1` | 255 |
| `hsv\|0\|1\|0.999` | **254** |

`0.999 × 255 = 254.745`，截断得 254。**饱和度或明度略小于 1 时颜色会暗一档。**

`clamp` 只兜住浮点误差导致的越界（例如上面的 `g = 1530`）。

**3. `murmurHash3Mixer` 用 `>>>`（逻辑右移），不是 `>>`。**

```java
public static int murmurHash3Mixer(int value) {
    value ^= value >>> 16;
    value *= -2048144789;
    value ^= value >>> 13;
    value *= -1028477387;
    return value ^ value >>> 16;
}
```

对负数 `value`，算术右移会把符号位带下来，散布特性完全破坏。两个乘数都是负数，在 32 位下
溢出环绕（与 [`mth_bit`](./mth_bit.md)、[`random_tick_pos`](./random_tick_pos.md) 同类的
二补数语义）。

| 单元 | 结果 |
|---|---|
| `murmur\|0` | **0**（0 是不动点） |
| `murmur\|1` | 1364076727 |
| `murmur\|-1` | -2114883783 |
| `murmur\|100` | -36807446 |
| `murmur\|101` | 1915844612 |
| `murmur\|102` | 1902775049 |

相邻输入 `100/101/102` 的输出差异巨大，说明扩散特性正常。

## ARGB 打包

```java
// ARGB.color(a, r, g, b)
return (a & 0xFF) << 24 | (r & 0xFF) << 16 | (g & 0xFF) << 8 | (b & 0xFF);
```

**每个通道都先 `& 0xFF`**，所以越界的通道值（如 `g = 1530`）会被截断到低 8 位——但在
`hsvToArgb` 里通道已经过 `clamp`，不会触发这个截断。

`hsva` 用例验证了 alpha 通道：`hsva(0, 1, 1, 255)` 得 `argb = -65536`（即 `0xFFFF0000`）。

## 未覆盖范围

- 负数色相（走 `default` 分支抛异常）
- `ARGB.alpha/red/green/blue` 的反解作为独立能力（本能力的输出已隐含验证）
- `Mth.murmurHash3Mixer` 在其他调用方（如方块实体哈希）的用法
