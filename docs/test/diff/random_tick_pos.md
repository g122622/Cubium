# 差分能力：`random_tick_pos`

> 由 `tests/diff/README.md` 拆分而来，记录该能力的实现要点、踩坑与验证结论。
> 跨能力共性规律见 [`_patterns.md`](./_patterns.md)。

第 112 个能力，16 个采样用例全部一致。随机刻的**坐标采样**此前未被覆盖
（[`crop_growth`](../../../tests/diff/README.md) 只覆盖了作物生长的结果）。

## ⚠️ 重要局限：本能力的 oracle 是复刻，不是直接调用

原版 `getBlockRandomPos` 是 `Level` 的**实例方法**，而 `Level` 是抽象类，正常构造需要
`LevelData`、`DimensionType` 与大量钩子对象。

尝试用 `sun.misc.Unsafe.allocateInstance` 分配未初始化实例，被 JDK 模块系统拒绝：
`IllegalStateException: 无法分配 Level 实例`。

**因此本 oracle 逐字符复刻原版方法体**，只借用原版的 `BlockPos` 构造函数：

```java
// 与 Level.getBlockRandomPos 的方法体逐字符相同
this.randValue = this.randValue * 3 + 1013904223;
int i = this.randValue >> 2;
return new BlockPos(x + (i & 15), y + (i >> 16 & maxY), z + (i >> 8 & 15));
```

**这削弱了本能力的置信度**：它验证的是「Cubium 的公式与我从源码抄下来的公式一致」，而不是
「与运行中的原版一致」。可能的误差来源：

- 我抄错了（已通读完整 4 行方法体，风险较低）
- 方法体之外还有影响结果的状态（`randValue` 的初值由外部设置，已在单元里显式给定）

代码只有 4 行、无外部依赖，且结果由原版 `BlockPos` 构造，**仍能捕获坐标加法与取位的实现
错误**。但不应把它当作与原版行为一致的强证据。

## 四个关键点

**1. `getBlockRandomPos` 不用 `Random` 对象，用独立的 `randValue` 整数状态。**

```java
protected int randValue = RandomSource.create().nextInt();
...
this.randValue = this.randValue * 3 + 1013904223;
```

这是一个 LCG（`x ← 3x + 1013904223`），**与世界的 `RandomSource` 完全隔离**。随机刻采样
不会消耗方块随机刻逻辑用的随机数流，反之亦然。

若把它实现成从 `Random` 取数，两者会互相干扰，导致**所有**随机行为错位——这是本条最重要的
实践含义。

**2. `int` 乘法必定溢出环绕。**

`randValue * 3` 在 32 位下会反复溢出。Java 的 `int` 溢出是定义良好的二补数环绕。用 `int64`
计算再截断到 32 位可得到相同结果，但**不能**用「不溢出的自然数算术」——那会立刻发散。

实测 `0|0|0|15|-2147483648|3` 与 `0|0|0|15|2147483647|3` 都正常产生坐标，溢出被正确环绕。

**3. `>> 2` 是算术右移。**

`randValue` 为负时算术右移补 1，`i` 也为负；后续 `i & 15` 才把它转成 `0..15`。若错用逻辑
右移（Java 的 `>>>`）会得到完全不同的坐标。

**4. 三个分量的取位间距不同。**

| 分量 | 取位 |
|---|---|
| X | `i & 15`（第 0~3 位） |
| Z | `i >> 8 & 15`（第 8~11 位） |
| Y | `i >> 16 & maxY`（第 16 位起） |

**X 与 Z 的间距是 8 位而不是 4 位**，所以采样点在水平面上不是「相邻 4 位」的规律。

## 实测结果

| 单元 | 采样结果 |
|---|---|
| `0\|0\|0\|15\|0\|1` | `7,11,12` |
| `0\|0\|0\|15\|0\|3` | `7,11,12; 15,14,3; 4,8,6` |
| `100\|64\|200\|15\|0\|3` | `107,75,212; 115,78,203; 104,72,206` |
| `-100\|-64\|-200\|15\|0\|3` | `-93,-53,-188; -85,-50,-197; -96,-56,-194` |
| `0\|0\|0\|3\|777\|3` | `14,3,15; 3,2,10; 1,0,11` |
| `0\|0\|0\|7\|777\|3` | `14,3,15; 3,6,10; 1,0,11` |

**起点偏移是纯加法**：`100/64/200` 加采样偏移得到 `107/75/212`，负起点同理。

**`maxY` 只影响 Y 的掩码**：同一个 `seed=777`，`maxY=3` 时 Y 为 `3,2,0`，`maxY=7` 时为
`3,6,10`，而 X 与 Z 完全不变。

## 一个反直觉的现象

`0|0|0|15|0|1` 与 `0|0|0|15|-1|1` **都得到 `7,11,12`**。

推演：

- `seed = 0`：`randValue = 0 * 3 + 1013904223 = 1013904223`
- `seed = -1`：`randValue = -1 * 3 + 1013904223 = 1013904220`

两者相差 3，而 `i = randValue >> 2` **丢弃低 2 位**，所以 `1013904220 >> 2 == 1013904223 >> 2`。

**初始 `randValue` 的末 2 位不影响第一次采样。** 这说明 LCG 的低位熵在首次采样时被右移
抹掉了一部分。

## 未覆盖范围

- `tickPrecipitation` 的 `random.nextInt(48) == 0` 判定
- `LevelChunkSection.isRandomlyTicking` 的门控
- `randomTickSpeed` 的配置来源与循环次数
- `randValue` 的初值生成（`RandomSource.create().nextInt()`）——本能力显式给定初值
