# 差分能力：`mth_seed`

> 由 `tests/diff/README.md` 拆分而来，记录该能力的实现要点、踩坑与验证结论。
> 跨能力共性规律见 [`_patterns.md`](./_patterns.md)。

第 138 个能力，22 个用例全部一致。`Mth.getSeed` 此前未被覆盖——它是结构生成、区块特性、随机刻
选址广泛依赖的「坐标 → 确定性种子」函数。

## 核心发现一：`x * 3129871` 是 `int` 乘法会溢出，`z * 116129781L` 是 `long` 乘法

```java
long i = x * 3129871 ^ z * 116129781L ^ y;
```

注意两个字面量的**后缀差异**：

| 表达式 | 字面量类型 | 运算位宽 | 是否溢出 |
|---|---|---|---|
| `x * 3129871` | `int` | **32 位** | **会回绕** |
| `z * 116129781L` | `long` | 64 位 | 不会 |
| `^ y` | `int` 提升为 `long` | 64 位 | — |

**这个不对称是 Java 数值提升规则的结果，不是笔误。**

| 单元 | 结果 |
|---|---|
| **`seed\|2147483647\|0\|0`** | **`121888977830720`** |
| **`seed\|-2147483648\|0\|0`** | **`70368743817216`** |
| `seed\|1000\|0\|0` | `-90802465359728` |

若 C++ 实现把 `x * 3129871` 写成 `static_cast<i64>(x) * 3129871`（64 位乘法），
`seed|2147483647|0|0` 会得到完全不同的值。

**探针的正确写法**：

```cpp
const i64 xTerm = static_cast<i64>(static_cast<i32>(static_cast<u32>(x) * 3129871U));
const i64 zTerm = static_cast<i64>(z) * 116129781LL;
```

先按 `u32` 做 32 位乘法，再转成有符号 `i32`（保留符号），最后扩展到 `i64`。

## 核心发现二：`y` 在异或链第三位且不乘系数

```java
x * 3129871 ^ z * 116129781L ^ y
```

`y` 只做**裸异或**，没有任何乘数。三者的系数完全不同（`3129871` / `116129781L` / `1`）。

交换任意两个坐标都会得到不同结果：

| 单元 | 结果 |
|---|---|
| `seed\|5\|3\|7` | `-112261771508756` |
| **`seed\|7\|3\|5`**（交换 x/z） | **`-80082258646495`** |
| **`seed\|5\|7\|3`**（交换 y/z） | **`54134975315381`** |

**哈希是方向敏感的**——`(5,3,7)` 与 `(7,5,3)` 完全不同，不存在「坐标顺序无关」的对称性。

### 一个真实的哈希碰撞

| 单元 | 结果 |
|---|---|
| **`seed\|0\|1\|0`** | **`645`** |
| **`seed\|0\|-1\|0`** | **`645`** |

`+1` 与 `-1` 在异或链中产生不同的 `i`，但经过 `i²·42317861 + i·11` 的变换后**恰好碰撞**。

这说明 `getSeed` **不是单射**——不能假设「种子不同 ⇒ 坐标不同」。

## 核心发现三：`z` 的符号敏感，`x` 的溢出掩盖了符号

| 单元 | 结果 |
|---|---|
| **`seed\|0\|0\|1`** | **`-20769809646864`** |
| **`seed\|0\|0\|-1`** | **`-20769809685848`** |
| `seed\|1\|0\|0` | `133076631897947` |
| `seed\|-1\|0\|0` | `133076631896896` |

`z` 与 `-z` 产生明显不同的值（`z` 进入 `long` 乘法，符号被完整保留）。

`x` 与 `-x` 也产生不同值，但差异**集中在低位**（`...947` vs `...896`）——因为 `x` 先经过 32 位
回绕乘法，高位符号信息在回绕中已经打散。

## 核心发现四：`i = i * i * 42317861L + i * 11L` 的两项用的是同一个原始 `i`

```java
i = i * i * 42317861L + i * 11L;
```

Java 的 `=` 右侧**整体求值后**才写入，所以 `i * 11L` 用的是**赋值前的 `i`**。

若 C++ 写成：

```cpp
i = i * i * 42317861LL;      // 先写回
i = i + i * 11LL;            // 错误：用的是平方后的 i
```

就会用平方后的 `i` 再乘 11，结果完全不同。

**探针的正确写法**：

```cpp
i = i * i * 42317861LL + i * 11LL;   // 单条表达式，与 Java 一致
```

## 核心发现五：返回 `i >> 16` 是算术右移，结果可为负

```java
return i >> 16;
```

**不是 `>>>`**。因此结果保留符号：

| 单元 | 结果 |
|---|---|
| `seed\|5\|3\|7` | **`-112261771508756`**（负） |
| `seed\|0\|0\|1` | **`-20769809646864`**（负） |
| `seed\|1000\|0\|0` | **`-90802465359728`**（负） |
| `seed\|0\|64\|0` | `2644866`（正） |

**约一半的坐标会产生负种子**。若 Cubium 用 `>>>`，所有结果都会变成非负，与结构生成的位置不匹配。

## 其余实测

| 单元 | 结果 | 说明 |
|---|---|---|
| **`seed\|0\|0\|0`** | **`0`** | 原点是哈希的不动点 |
| `seed\|0\|64\|0` | `2644866` | 实际常见坐标 |
| `seed\|128\|-64\|-256` | `73906427483091` | |
| `seed\|-16\|70\|32` | `42906627473683` | |

**`getSeed(0,0,0) = 0`**：`i = 0`，`0*0*... + 0*11 = 0`，`0 >> 16 = 0`。

### `Vec3i` 重载与三参重载完全一致

| 单元 | 结果 |
|---|---|
| `vec\|5\|3\|7` | `-112261771508756` |
| `seed\|5\|3\|7` | `-112261771508756` |
| `vec\|128\|-64\|-256` | `73906427483091` |
| `seed\|128\|-64\|-256` | `73906427483091` |

`getSeed(Vec3i)` 只是拆包后转调三参版本，无额外变换。

## 本轮情况：一次通过

写代码前完整读取了 `getSeed` 的实现，**特别注意了两个字面量的 `L` 后缀差异**——这是最容易写错
的地方。探针用显式的 `static_cast<u32>` 32 位乘法来复刻 `int` 回绕。

## 输出格式：64 位整数必须用字符串

`getSeed` 的结果是 `long`，绝对量级可达 `10^14`，**远超 JavaScript 的
`Number.MAX_SAFE_INTEGER`（`2^53-1 ≈ 9×10^15`）** 附近，且探针与 oracle 都按十进制字符串输出。

harness 若把 `value` 当数字解析，`-112261771508756` 这类值仍可精确表示，但为稳妥起见两侧
统一按**字符串**对比——与 `BlockPos.asLong` 等已有能力的约定一致。
