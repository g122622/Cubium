# 区块运行时分层重构

## 已确认的设计

区块子系统以 `server/world/chunk/ServerChunkManager` 为唯一生产入口。
`world/scheduling/` 独立保留，提供生成、光照、网络序列化共享的区域执行设施。
世界根目录中的生成文件迁入区块子系统，运行时光照文件迁入 `lighting/runtime/`。
`chunk/base/request/` 和 `chunk/base/completion/` 分别保留。

不保留旧文件、旧 API 别名或兼容转发头。共同使用的坐标和区块数据模型留在 common；
服务端专属票据、距离传播和玩家追踪迁入 `chunk/lifecycle/demand/`。

## 文件与所有权

| 模块 | 状态与职责 | 依赖 |
|---|---|---|
| ServerChunkManager | 对外请求、查询、需求、tick 和关闭操作 | 生命周期控制器 |
| ChunkLifecycleController | 根据状态机决策编排来源解析、生成和交付 | 各内部能力模块 |
| ChunkRegistry | 坐标到当前 holder 的索引、FULL 数据索引、统一发布和移除 | ChunkHolder、公共区块数据 |
| ChunkHolder | 单区块来源、阶段、请求聚合、活跃任务身份、邻居保活 | 阶段规则、请求值 |
| ChunkDemandController | 票据、距离传播、玩家加载范围与追踪集合 | 距离图与票据值 |
| ChunkSourceLoader | 在途读档合并、来源完成队列、身份校验 | 存储入口、注册表、交接协议 |
| ChunkGenerationScheduler | 双向生成依赖图、任务身份及取消确认 | 注册表、步骤执行器、区域执行器 |
| ChunkProgressionTask | 单阶段执行与完成通知，保活全部邻居 | 步骤执行器、生成回调 |
| ChunkStepExecutor | 生成阶段算法分派、生成上下文与活动时间 | IChunkGenerator、上下文与光照回调 |
| ChunkUnloadController | 候选、异步快照保存、最终复核、冷却与重试 | 注册表、需求、生成、来源、退场接口 |
| WorldChunkLifecycle | 主线程世界注册、实体、tick、方块后处理和退场通知 | ServerWorld、光照与网络接入 |
| ChunkDiagnostics | 保活快照上的状态与内存诊断 | 注册表的只读查询 |
| AreaTaskScheduler | 区域执行资格、取消和完成 | ITask、外部计算池 |

生产世界持有一个 AreaTaskScheduler。独立生成运行时显式持有自己的实例；
线程池始终由调用方持有，关闭前必须保证服务对象和所有异步回调的生命周期。
区块运行时不持有网络发送管理器；世界及维度负责网络接入。

## 核心契约

### 数据就绪与世界激活

- 来源解析状态、已完成生成阶段、FULL 发布、世界激活、光照可发送和模拟资格分别表达。
- 中间阶段请求达到自己的目标即可交付，不等待更高阶段。
- 存档区块在交接前已经由存储层补齐高度图；接收路径不重复全量扫描。
- 来源状态与 primer 对象一并安装，不能先宣告就绪再安装数据。
- FULL 索引共享 holder 的 ChunkData，不形成另一份权威数据。
- 生成 LIGHT 步骤在区域执行保护下完成；世界注册、实体生成和 tick 注册在主线程完成。
- 激活完成消息保活原 holder 并校验当前实例，旧生命周期消息不能激活同坐标的新实例。
- 每个生命周期只执行一次世界注册；生成后处理等待进入模拟范围。

### 并发与完成

- 调度区域锁保护依赖图、任务身份、请求登记与最终退场复核。
- AreaTaskScheduler 保护生成、光照、序列化的重叠执行区域。
- shared_ptr 只保证存活，不能替代阶段校验或数据访问同步。
- 取消只置位信号；任务身份和实际登记的邻居保活保留到执行器确认退出。
- 已开始修改区块的步骤按既有契约完成，再读取最新需求决定是否继续。
- 请求回调保留原有数据交付线程语义；触及世界的激活通知独立延后至主线程。
- 完成接收消费入口快照，预算耗尽后旧项排在新项之前；来源完成接收保留重入保护。
- 异步存储回调只持有可独立存活的完成接收端，关闭后不访问已销毁的运行时服务。

### 卸载与关闭

- 候选来自安全性变化通知，执行时重新校验，保留事件驱动回收和空闲 halo 门控。
- 快照保存失败时保留区块并恢复脏状态；保存后再次变脏时中止退场。
- 保存完成只影响发起保存的生命周期实例。
- 无脏数据也通过完成队列延后复核，保留相邻 tick 返回需求的窗口。
- 当前需求、未完成请求、邻居保活、活跃任务、冷却和保存状态共同约束退场。
- 世界退场和网络预卸载分别有唯一执行路径。
- 关闭先阻止新需求及重调度，再关闭世界区域任务，等待计算任务和回调，最后释放状态。
- 存储内部结清在途保存；区块运行时不再通过 friend 清理存储私有追踪表。

## 迁移与核验顺序

1. 记录现有服务端与 benchmark 二进制时间戳、源码提交和基线参数。
2. 迁移散落文件、服务端需求系统和阶段模型，更新全部包含与 CMake 唯一编译归属。
3. 提取请求值与完成接收基础设施，删除 holder 中无人写入的票据和追踪副本。
4. 引入注册表统一发布和移除，收敛数据与状态的一致性边界。
5. 抽出来源加载器、步骤执行器和世界接入，保留现有生成依赖算法。
6. 生成调度器与任务改为使用注册表、执行器和明确交接协议，移除门面 friend。
7. 提取卸载流程及其所有队列和策略；集中生命周期身份校验。
8. 门面改为委托控制器，外部调用改用需求操作和查询。
9. 区域执行器归世界所有，网络和光照直接使用世界执行服务。
10. 更新模块 README 与项目约定；清除旧头文件、旧接口和残留引用。
11. 编译服务端、相关单测和 benchmark；只运行本子系统相关测试。
12. 复跑相同 stress 和 benchmark 参数，保存对照结果。
13. 每次编译前格式化 src、tests、benchmark 全部 C++ 代码；检查编码和 diff，提交最终实现。

## 验证范围

定向覆盖 ServerChunkManagerTest、ServerChunkManagerCallbackTest、
ServerChunkManagerPostProcessTest、ChunkGenerationDemandTest、AreaTaskSchedulerTest、
BlockUpdateSyncManagerTest 以及加载光照相关用例。
新增验证重点是旧生命周期激活消息、异步存储完成接收端关闭、发布身份和退场失败结果。
不运行全量单元、集成或差分测试，不建立额外工作树或基线构建。

性能使用普通世界、固定种子与新存档。压力测试为单玩家 64 格/秒移动 8 秒，
视距和模拟距离均为 4，预热 2 秒、基线 3 秒、恢复 5 秒，并显式豁免速度阈值。
生成基准为 1/4/8 线程、每批 8×8 个 FULL 区块、单次迭代、重复 3 次，关闭 trace。
基线产物位于 `build/stress/chunk-layering-before/` 和 `build/benchmark/chunk-layering-before/`。
基线 benchmark 是 2026-11-12 的既有二进制，源码及二进制时间戳保存在
`build/chunk-layering-baseline.json`；性能结果必须带此限制解读。

## 验证结果

服务端、单测和 benchmark 的 RelWithDebInfo 构建成功。定向单测 9 组共 92 项全部通过，
覆盖关闭后的完成消息、完成预算顺序、旧实例发布与激活、带符号坐标卸载和非法生成步骤断言。
压力测试脚本检查 11 项全部通过；全仓库 8905 个文本文件通过 UTF-8 编码校验。

相同参数的压力测试前后均通过。覆盖复核移动 512 格，收取和卸载各 288 个区块，
最终客户端视距所需的 81 个区块全部存在。移动阶段 tick P95 从 8.11 ms 到 8.80 ms，
最长 tick 从 11.43 ms 到 20.03 ms，峰值工作集从 166 MiB 到 168 MiB；
无超过 50 ms 的 tick、掉线、崩溃或位置回弹，恢复后均为 90 个已加载区块、121 个 holder。

各档位均成功完成，没有错误或超时。8 线程耗时略增，前测波动和既有二进制限制使这轮结果
只能用于筛查明显异常，不能单独判断重构带来的优化或回归。
