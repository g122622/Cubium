# 登录与区块 tick 性能里程碑

2026-10-17，在 Windows RelWithDebInfo 构建上分析登录 trace，并通过真实 Java wire bot 复测。视距 16、模拟距离 4；每次使用同一停止状态的 native 存档副本，未修改用户原存档或原始 trace。

## 改动

- 存档加载线程补齐缺失高度图；公共重建算法跳过空段，并在找到列顶后提前结束。
- 登录只建立加载需求；区块结果交接、实体恢复及后处理由后续 tick 分批推进。
- 生成调度与存档就绪邻居通知在工作线程获取区域锁；票据更新和卸载收尾使用尝试加锁，繁忙时保留任务重试。
- 存档完成、后处理、票据传播和卸载设置墙钟预算；保持旧完成项优先及同步请求等待语义。
- 批量区块发送释放 LIGHT 票据后统一传播，避免逐区块重复推进距离图。
- 命令树规范路径一次深度优先收集，保留共享节点首路径和重定向语义。
- 方块 tick 范围独立于加载视距；实体模拟距离 4 时，方块保留一圈邻居，随机刻范围由 961 个区块减为 121 个。强显式票据保留其传播范围。
- 第三方客户端所需注册表 NBT 在启动注册数据包来源时准备，重新注册来源会重建快照。
- 增加区块队列、生物更新阶段和寻路追踪，供后续分析尖峰。

## 结果与限制

第一阶段各交替运行三次，`sendInitialGameState` 中位数从原程序的 255.71 ms 降为 29.78 ms。

下表为第一阶段程序与里程碑程序的一组交替复测。该轮尚未包含后续注册表初始化顺序与重载失效修正。两侧收到前 64 个区块后继续观察 10 秒；tick 统计包含玩家在线期间的全部 CSV 行，不包含登录前 Configuration 阶段。

| 指标 | 第一阶段 | 本里程碑 |
|---|---:|---:|
| sendInitialGameState | 27.69 ms | 1.50 ms |
| 命令树构建 | 17.17 ms | 1.43 ms |
| 最大网络轮询（含登录前配置） | 52.50 ms | 6.81 ms |
| 在线期间最大 tick | 252.88 ms | 31.74 ms |
| 在线期间 P95 tick | 42.87 ms | 18.57 ms |
| 在线期间 P99 tick | 72.36 ms | 22.61 ms |
| 超过 20 ms 的 tick | 58 / 177 | 9 / 209 |
| 客户端收到前 64 个区块，自连接开始 | 1218.20 ms | 784.71 ms |

尚未达到所有 tick 稳定低于 20 ms。最终 trace 的单次寻路仍可耗时约 10.28 ms。此前中间版本三组较长复测的 P95 为 20.15–35.64 ms，说明负载与调度波动仍影响尾部延迟。

初始化顺序修正后的再次对照（`series-1792233051196`）中，初始状态下发 32.82→1.78 ms，最大 tick 211.29→46.10 ms，P95 76.84→31.29 ms，超过 20 ms 的 tick 为 129/215→78/177，客户端前 64 区块 2788.99→893.18 ms。该轮同时进行收尾测试，不能与上表作为相同机器负载比较；其意义在于确认真实登录成功，且注册表标签未解析错误消失。两组结果均不能支持“稳定低于 20 ms”。

观察结束时两侧未达到相同加载状态：本里程碑保留约 2398 个区块、481 个实体，第一阶段约 1224 个区块、363 个实体；RSS 分别约 462 MiB 和 328 MiB。不能据此声称区块加载吞吐、最终内存或稳态延迟已完全等价。墙钟测量也包含操作系统调度，未做 CPU 独占。
