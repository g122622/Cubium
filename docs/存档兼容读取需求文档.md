### 一、中间表示 (IR) 层

#### 1.1 ChunkerBlockIdentifier — 方块标识

核心数据结构：

```
ChunkerBlockIdentifier
├── type: ChunkerBlockType          // 方块类型 (Vanilla / Custom)
├── states: Map<BlockState<?>, BlockStateValue>  // 状态属性 (朝向、含水等)
└── preservedIdentifier: PreservedIdentifier?     // 同格式转换时保留原始标识
```

- **不可变 + 写时复制**：`copyWith()` / `copyWithout()` 返回新实例，保证线程安全
- **享元模式**：`AIR` 是静态单例，避免大量空气方块重复创建
- **状态查找带默认值**：`getState(blockState, returnDefaultValue)` — 若 states map 中无此 key，回退到方块类型的默认值

#### 1.2 Palette 调色板存储体系

这是内存优化的核心。层次结构：

```
Palette<T> (接口)
├── EmptyPalette<T>       // 空区块单例
├── SingleValuePalette<T> // 全部相同方块 (如全空气)
└── ShortBasedPalette<T>  // 完整调色板
      ├── keys: List<T>           // 去重后的唯一值列表
      └── values: short[][][]     // 16×16×16 索引数组 → 指向 keys
```

**ShortBasedPalette 内存优化策略：**

1. **键去重** — `keys` 只存唯一值，`values` 存索引（short = 2 字节 vs 对象引用 8 字节）
2. **compact() 方法** — 转换后清理不再使用的键，重新映射索引，若仅剩1个键则降级为 `SingleValuePalette`
3. **按需升级** — `setBlock()` 时自动将 `EmptyPalette` / `SingleValuePalette` 升级为 `ShortBasedPalette`

compact 算法核心流程：
```
遍历 values 三维数组 → 收集实际使用的 key 索引 →
重建 keys 列表 (去重) → 生成 paletteRemapping 表 →
原地更新 values 中的索引 → 若 keys.size()==1 返回 SingleValuePalette
```

#### 1.3 ChunkerColumn — 列（16×16 垂直柱）

```
ChunkerColumn
├── position: ChunkCoordPair
├── chunks: Byte2ObjectSortedMap<ChunkerChunk>  // 按 Y 有序的子区块
├── entities: List<Entity>
├── blockEntities: List<BlockEntity>
├── biomes: ChunkerBiomes?
├── heightMap: HeightMap?
├── requiredPreTransformEdges: Set<Edge>         // 依赖的邻居方向
└── preTransformHandler: Consumer<Map<Edge, ChunkerColumn>>  // 邻居就绪后的回调
```

**关键算法 — 最高方块查找 `getHighestBlock()`：**
```
从 chunks 有序映射的尾部开始反向迭代 →
找到包含非空气方块的 chunk →
在该 chunk 内从 y=15 向下扫描 →
返回 (globalY, blockIdentifier)
```

**方块访问 `getBlock(x, y, z)`：**
```
chunkY = y >> 4                    // 定位子区块
localX = x & 15, localY = y & 15, localZ = z & 15  // 局部坐标
→ chunks[chunkY].palette.get(localX, localY, localZ)
```

### 二、Pipeline 管道系统

#### 2.1 嵌套 Handler 链

Pipeline 采用 **装饰器链** 模式，三级嵌套：

```
LevelConversionHandler
  └─ convertLevel(level) → Task<WorldConversionHandler>
       └─ convertWorld(world) → Task<ColumnConversionHandler>
            └─ convertColumn(column)
            └─ flushRegion(region)
            └─ flushColumns()
```

每一级的 `convert*()` 返回下一级 handler，形成自然的流式转换：

```
LevelHandler (维度映射 + 设置合并)
  → PipelineLevelConversionHandler (异步包装)
    → LevelWriterConversionHandler
      → WorldHandler (维度重映射)
        → PipelineWorldConversionHandler (异步包装)
          → WorldWriterConversionHandler
            → ColumnPreTransformHandler (邻居依赖解决)
              → PipelineColumnConversionHandler (异步包装)
                → ColumnWriterConversionHandler
```

Handler 组合算法：
```java
// 多个 handler 通过 andThen 链式组合
static <T> Function<T, T> compose(Function<T, T>... handlers) {
    Function<T, T> fn = handlers[0];
    for (int i = 1; i < handlers.length; i++) {
        fn = fn.andThen(handlers[i]);  // handler[0] → handler[1] → ...
    }
    return fn;
}
```

#### 2.2 异步任务系统

**Task 接口** — 类似 CompletableFuture 但增加了：
- 命名任务（调试用）
- **权重进度追踪**（父子层次化）
- **优先级调度**（深度越深优先级越高）

```
TaskWeight:
  NONE=0, LOW=1, MEDIUM=50, NORMAL=100, HIGH=200, HIGHER=500, HIGHEST=1000
```

**进度计算算法：**
```
getProgress():
  if PENDING → 0
  if DONE    → 1
  if STARTED with children:
    totalWeight = selfWeight + Σ(child.weight)
    progress = Σ(child.progress × child.weight) / totalWeight
```

**TaskExecutor** — 基于 `PriorityBlockingQueue` 的线程池：
- 优先级 = 任务深度（越深的子任务越先执行，减少阻塞）
- `InheritableThreadLocal` 传递 executor 上下文
- 工作线程数：默认 8

**Environment** — 管理任务执行器生命周期：
```
创建 → start() → 提交任务 → close() → 等待子任务完成 → 清理
                                        ↑ 可被 cancel(exception) 中断
```

### 三、Pre-Transform 预变换系统

处理需要邻居区块信息的方块（门、栅栏、红石等），核心是 **依赖图求解**。

#### 3.1 Edge 和 ColumnData

```
Edge: POSITIVE_X(+1,0), NEGATIVE_X(-1,0), POSITIVE_Z(0,+1), NEGATIVE_Z(0,-1)

ColumnData:
├── position: ChunkCoordPair
├── column: ChunkerColumn
├── requiredColumns: Map<Edge, ColumnData>   // null=未解析
├── pendingCheckEdges: EnumSet<Edge>          // 待检查的边
└── submitted: boolean                        // 是否已提交
```

#### 3.2 求解算法

**阶段一 — 提交列 (`convertColumn`)：**
1. 获取列的 `requiredPreTransformEdges`
2. 初始化 `pendingCheckEdges` = ALL_EDGES
3. 调用 `solveColumn()`

**阶段二 — 边解析 (`solveEdge`)：**
```
对于边方向 edge:
  查找邻居列 →
    不存在 & 区域未完成 → return false (等待)
    不存在 & 区域已完成 → return true  (邻居为空，移除依赖)
    存在 → 双向链接，若邻居不再有依赖则立即提交
```

**阶段三 — 聚类求解 (`trySolve`)：**
使用 DFS 找出可一起解决的最大连通分量：
```
DFS 从当前列出发:
  遇到有 pending checks 的节点 → 失败
  遍历所有 requiredColumns 邻居 →
    全部可达且无 pending → 缓存到 cachedChecking
所有 cachedChecking 中的列作为一个 cluster 一起解决
```

**阶段四 — 执行变换 (`transformCluster`)：**
```
对 cluster 中每列:
  调用 column.preTransformHandler(requiredColumns)
  → 触发具体方块处理（栅栏连接、门状态复制等）
对 cluster 中每列:
  提交到下一个 handler
```

#### 3.3 方块连接处理示例

**栅栏连接判断：**
```java
canConnect(source, direction, relative):
  if relative 是 FenceGate:
    return relative.facing 是 direction 的相邻方向
  if relative 是 WoodenFence:
    return true
  if relative.isAllFacesSolid():
    return true
  return false
```

**门状态同步：**
- 上半部分 → 复制铰链状态到下半部分
- 下半部分 → 复制开关状态和朝向到上半部分

**方块相对位置查找 (`getRelative`)：**
```
direction.getEdge() != null:
  newChunkX = (x + edge.x) >> 4
  newChunkZ = (z + edge.z) >> 4
  跨区块 → 从 neighbours map 查找
  同区块 → 直接查当前列
```

### 四、编码层 — 格式读写

#### 4.1 Java Anvil 格式 (.mca 区域文件)

**字节布局：**
```
┌─────────────────────────────┐
│ 偏移表 (4096 bytes)          │  1024 × 4 bytes: [3字节偏移][1字节扇区数]
│ 时间戳表 (4096 bytes)        │  1024 × 4 bytes: unix timestamp
├─────────────────────────────┤
│ 扇区数据...                  │
│  ┌────────────────────────┐ │
│  │ 长度 (4 bytes)         │ │
│  │ 压缩类型 (1 byte)      │ │  0=空, 1=GZip, 2=ZLib, 3=无, 4=LZ4
│  │ 压缩的 NBT 数据        │ │
│  └────────────────────────┘ │
│  (如果压缩类型 & 0x80 != 0  │   → 数据在外部 .mcc 文件)
└─────────────────────────────┘
```

每个扇区 = 4096 字节。区块数据起始于 `offset × 4096`。

#### 4.2 Bedrock LevelDB 格式

**键结构：**
```
[chunkX: 4B LE] [chunkZ: 4B LE] [dimensionID?: 4B LE] [type: 1B] [subChunkY?: 1B]
                                                                  ↑ 仅 SUB_CHUNK_PREFIX
                                        ↑ 仅非 OVERWORLD
```

**键类型表：**

| Type ID | 名称             | 内容                   |
| ------- | ---------------- | ---------------------- |
| 43      | DATA_3D          | 高度图 + 3D 生物群系   |
| 44      | VERSION          | 单字节版本号           |
| 45      | DATA_2D          | 高度图 + 2D 列生物群系 |
| 47      | SUB_CHUNK_PREFIX | 方块数据 (调色板)      |
| 49      | BLOCK_ENTITY     | 方块实体 NBT           |
| 50      | ENTITY           | 实体 NBT               |

**LevelDB 配置：**
```java
compressionType(ZLIB_RAW)
blockSize(160KB)
filterPolicy(BloomFilter(10))  // 布隆过滤器加速查找
```

**子区块读取：**
```java
byte[] key = LevelDBKey.key(dimension, position, (byte)0, SUB_CHUNK_PREFIX);
for (byte y = -64; y < 64; y++) {
    key[key.length - 1] = y;  // 只改最后一个字节
    byte[] value = database.get(key);
    // 解析调色板数据...
}
```

#### 4.3 Bedrock 调色板编解码

```
读取流程:
1. paletteData = buffer.get() & 0xFF
2. bitsPerEntry = paletteData >> 1
3. runtimeEncoding = paletteData & 0x1
4. 若 bitsPerEntry == 127 → EmptyPalette
5. 计算 valuesPerWord = floor(32 / bitsPerEntry)
6. 计算 wordSize = ceil(4096 / valuesPerWord)
7. 跳过 wordSize 个 int (位压缩数据)
8. 读取 keys 列表 (调色板条目)
9. 回到位压缩数据，解码每个 x,y,z 位置的索引
10. 若 keys.size()==1 → SingleValuePalette
    否则 → ShortBasedPalette
```

### 五、解析器系统 (Resolver)

#### 5.1 核心接口

```java
interface Resolver<T, U> {
    Optional<U> to(T input);    // 格式特定 → Chunker IR
    Optional<T> from(U input);  // Chunker IR → 格式特定
}
```

支持三种组合操作：
- `then(otherResolver)` — 链式管道
- `inverse()` — 反转 to/from
- `cached()` — Caffeine 缓存包装

#### 5.2 ChunkerBlockIdentifierResolver — 方块解析

**数据结构（双向映射）：**
```java
// 输入 → Chunker
Map<String, InputStateGrouping<String, Object, ChunkerBlockType, BlockState<?>, BlockStateValue>> inputToChunker

// Chunker → 输入
Map<ChunkerBlockType, InputStateGrouping<BlockState<?>, BlockStateValue, String, String, Object>> chunkerToInput
```

**解析算法（输入 → IR）：**
```
1. 用标识符字符串查 inputToChunker map
2. 在 StateGroup 中按最大状态集匹配
3. 剩余状态通过 StateMappingGroup 转换
4. 无匹配 → 保留为 Custom block 或返回 AIR
```

**注册方式（5种）：**
- `register()` — 标准双向映射
- `registerOverrideInput()` — 覆盖输入方向
- `registerOverrideOutput()` — 覆盖输出方向
- `registerDuplicateInput()` — 多个 IR 方块 → 同一输入
- `registerDuplicateOutput()` — 同一 IR 方块 → 多个输出

#### 5.3 StateMappingGroup — 状态映射

```
StateMappingGroup
├── states: List<StateMapping<?, ?>>
├── defaultInputs: Map<String, Object>          // 输入方向默认值
└── defaultOutputs: Map<BlockState<?>, BlockStateValue>  // 输出方向默认值

StateMapping<I, O>
├── inputStateNames: List<String>               // 如 ["facing_direction"]
├── outputBlockStates: List<BlockState<? extends O>>  // 如 [FACING]
└── typeMapping: TypeMapping<I, O>
      ├── inputToOutput: Map<List<I>, List<O>>
      ├── outputToInput: Map<List<O>, List<I>>
      ├── defaultInput: List<I>
      └── defaultOutput: List<O>
```

支持 **多对多状态映射**：一个输入状态组映射到多个输出状态，例如 Bedrock 的 `facing_direction` (0-5) 映射到 Java 的 `facing` (north/south/east/west) + `half` (top/bottom)。

#### 5.4 KeyedHierarchyBasedResolver — 方块实体/实体解析

用于 `BlockEntityResolver` 和 `EntityResolver`：

```
按 key (方块实体ID/实体类型) 查找 handler →
  按类继承层次从基类到派生类依次调用 →
    construct() → read() / write()
```

支持 **接口 handler**（如 `GenerateBeforeProcessBlockEntityHandler`）用于横切关注点。

**TypeHandler 模式：**
```java
abstract class TypeHandler<R, K, D, T> {
    K getKey();              // 如 "minecraft:chest"
    Class<T> getHandledClass();  // 如 ChestBlockEntity.class
    T construct();           // 创建 IR 实例
    void read(R, D, T);     // 格式数据 → IR
    void write(R, D, T);    // IR → 格式数据
}
```

**未知类型保留：** 当 `preserveUnknownEntities=true` 时，无法识别的方块实体/实体被保存为 `UnknownBlockEntity`/`UnknownEntity`，实现同格式转换的保真度。

#### 5.5 版本继承模式

```java
// Bedrock v1_21 Reader 继承 v1_20_60 Reader
public class LevelReader extends com.hivemc.chunker...v1_20_60.reader.LevelReader {
    @Override
    public @Nullable Object readCustomLevelSetting(...) {
        if (targetName.equals("R21Support")) return true;  // 新版本新增设置
        return super.readCustomLevelSetting(...);           // 其余委托给父版本
    }
}
```

版本注册使用 `floorEntry()` 查找最近编码器：
```java
static Optional<BedrockLevelReader> createReader(File dir, Converter converter) {
    Optional<BedrockDataVersion> version = BedrockDataVersion.detect(dir);
    BedrockEncoder encoder = getNearestEncoder(version);  // floorEntry
    return encoder.readerConstructor().construct(dir, version.get(), converter);
}
```

### 六、生物群系 (Biome) 系统

| 存储方式                           | 分辨率                        | 适用版本                       |
| ---------------------------------- | ----------------------------- | ------------------------------ |
| `ChunkerColumnBasedBiomes`         | 16×16 (每列1个)               | Java pre-1.18, Bedrock DATA_2D |
| `ChunkerPaletteBasedBiomes`        | 16×16×16 (每子区块一个调色板) | Java 1.18+, Bedrock DATA_3D    |
| `ChunkerClusterBasedBiomes`        | 4×4×4 簇 (每子区块64个值)     | Java 1.18+                     |
| `ChunkerClusterPaletteBasedBiomes` | 簇 + 调色板                   | Java 1.18+ 扩展                |

**Java 1.18+ 生物群系读取：**
```
sections[].biomes.palette → 调色板键列表 (生物群系名字符串)
sections[].biomes.data    → long[] 位压缩索引值
使用 PaletteUtil 解压 → ShortBasedPalette 或 SingleValuePalette
```

**Java 调色板位压缩 (PaletteUtil)：**
- 使用 `long[]` 数组存储位压缩数据
- 两种格式：1.13 连续压缩 vs 1.16 Mojang magic values（更快除法）
- 最小 bits per entry：方块=4，生物群系=1

### 七、整体数据流图

```
┌──────────────┐     ┌──────────────────────────────────────────────────┐     ┌──────────────┐
│  Java Anvil  │     │                Chunker IR                         │     │ Bedrock LevelDB│
│  (.mca)      │     │                                                   │     │              │
│  GZip/ZLib   │────▶│  ChunkerLevel                                    │────▶│  ZLIB_RAW    │
│  Big-endian  │     │  ChunkerWorld  (维度)                             │     │  Little-endian│
│  NBT         │     │  ChunkerColumn (列)                               │     │  NBT          │
│              │     │  ChunkerChunk  (子区块, Palette存储)               │     │              │
│  Region文件  │◀────│  ChunkerBlockIdentifier (方块+状态)               │◀────│  LevelDB KV  │
│  扇区偏移表  │     │  ChunkerBiome (4种布局)                           │     │  键=坐标+类型 │
│              │     │  Entity / BlockEntity                             │     │              │
└──────────────┘     └──────────────────────────────────────────────────┘     └──────────────┘
                            ▲                         ▲
                            │ Resolver                │ Resolver
                     (BlockIdentifier)         (Biome/Entity/Item)
                            ▲                         ▲
                     ┌──────┴─────────────────────────┴──────┐
                     │         版本特定编码器                  │
                     │  Java: v1_8 → v1_21 (继承链)          │
                     │  Bedrock: v1_12 → v1_21 (继承链)      │
                     └───────────────────────────────────────┘
```

这本质上就是一个 **编译器架构**：源格式 → 解析 → IR → 优化变换 (Pre-transform) → 代码生成 → 目标格式，只是应用在了 Minecraft 世界数据上。
